# 2.0.4-probe.5：基于真机证据修正图片识别，手动选图裁图

## 真机日志结论

- 评论图片菜单可读：“分享评论给”“保存到相册”“识别图片”，独立窗口。这解决了此前“是否读得到菜单”的未知，仍不能从菜单知道长按的是哪张图片。
- 表情包菜单是“添加到表情”，与评论图片菜单不同，不能套用同一触发条件。
- 评论图片节点className为空、contentDescription为“图片”；旧版只检查class，错误标记mediaCandidate=false。现已补充描述匹配。“图片表情”也记录为候选。
- 日志中的表情节点visible=false，bounds底部反向，不能拿来裁图。
- 普通分享那组保存的是评论列表，没有实际分享面板证据；候选=false不等于排他性验证通过。
- 采样结束后S3仍显示“采样中”是状态更新缺陷，已修复；时间戳里的字面SSS也已修复。

仅记录结构性结论，不在公开源码中放用户原始评论/联系人文字。

## 用户主动选图取图入口

验证工具点“5秒后选取抖音评论图片”，切到评论列表，手动关闭长按/分享/添加表情菜单，停止滚动。

读取当前活动/焦点抖音窗口，在已记录的评论行id/fmu上下文内寻找可见、正面积的“图片/图片表情”节点，最多6张。评论行父子关系是需真机验证的适配假设：不满足就记录COMMENT_SCAN计数并阻断，不能随意放宽到所有ImageView（会截到头像和输入按钮）。菜单仍开着、树被截断、多窗口或无可靠候选时阻断。

先截图再显示临时选图面板，避免本应用面板覆盖源图。截图前后重新核对候选window/bounds及旋转；截图与节点坐标尺寸不一致或区域越界时拒绝猜测缩放。裁图的像素来自这一张冻结截图，之后即使页面滚动也不改用新坐标。

用户从内存预览中明确点选一张，才创建私有JPEG缓存，调用已在用户设备显示成功的Android16实时通知路径；旧系统仅发原焦点协议探针。临时面板是明确标记的选图UI，不冒充系统岛。未选择则20秒结束；预览不写磁盘或相册，只有主动点岛上保存才写相册。取消/总开关关闭/服务断开/其他显示操作会令旧回调失效。

此入口验证“截图裁剪→用户确认目标→官方系统岛→保存/分享”，**不是自动长按**。压暗与否、真实节点父子关系和显示效果必须真机检查。动态表情仅当前帧，不提取原GIF/视频。

## 采样修正

图片菜单和“添加到表情”分别保留；只有评论列表的普通分享组明确报证据不足。普通分享候选的标签规则仅用于采样提示，未得到真机验证，不授权自动点击或自动截取。三组已有结果不再等同于三组有效面板证据。

## 仍缺少的验证

自动长按原触点/准确目标关联、菜单出现前的未压暗截图、普通分享真实对照。未实现自动点抖音保存，未接入Root/Shizuku/触摸探索，不从多张图片中猜一张。
