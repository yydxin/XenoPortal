# 2.0.3-probe.4：岛上直接保存与抖音分组采样

## 已取得的真机反馈

用户在2026-11-11提供了probe.3截图：桌面顶部有XenoPortal“验证中”系统岛，展开系统通知中含保存/微信/QQ。用户确认应用内看不到，离开应用可见。记录为该设备和该构建的人工观察，不推断所有HyperOS版本行为，也未取得该次系统返回的promoted字段。应用内抑制显示的具体原因未确认，本次不强制改变。

## 本次改变

岛上的“保存到相册”使用显式、不可变的Broadcast PendingIntent，接收器exported=false。只写入本应用有效缓存会话，经MediaStore写入Pictures/XenoPortal并结束IS_PENDING；不启动Activity、不申请额外读取或前台服务。点击后取消超时及通知，防止写入时缓存被显示超时清除；保存期间缓存清理避开正在写入的会话，重复点击跳过。成功后清理未共享源图，Toast反馈；失败清理本次插入的pending行、保留缓存供重试、记录S7。微信/QQ等其余目标保持现有行为。

分组采样：验证工具可分别采集评论图片、评论表情包、普通分享面板，每组最长60秒，需用户先开启总开关、无障碍和窗口文字树调试。只读取抖音窗口，记录每组快照、候选前2秒内的前置快照和图片节点；三组分开保留，完整导出包含三组。复制报告过大时转为明确标记的摘要，完整内容用分享导出。

候选锚点“分享评论给”和“保存到相册”必须在同一个窗口，避免跨窗口拼接。候选不证明长按，更不证明原触点；普通分享若也命中则明确报告不具排他性。限频丢弃的相关事件补一次延时采样，避免菜单仅发一次事件时被直接丢弃。增加节点longClick/visible元数据供后续审查。

## 边界

这一步尚未实现自动长按定位、未压暗裁图、自动点击抖音保存，没接入Root/Shizuku/触摸探索。不得将节点图片类别或两段菜单文字当作排他证据。表情包截图只能保留静态帧；原文件/GIF/视频提取也尚未接入。

验收顺序：先验证岛上直接保存不打开页面且相册只有一份；再采集三组菜单。真实菜单与目标区域确认后再实现取图，不用显示层成功代替触发层验收。
